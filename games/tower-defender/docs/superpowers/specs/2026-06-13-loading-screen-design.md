# 加载屏动效设计文档

## 背景与目标

《成都保卫战 · 三国塔防》初次进入游戏时，`main.js` 的 `boot()` 会先 `await preload()` 并行加载约 80 张图片资源（武将立绘、敌军、Boss、建筑）。这段白屏期没有任何视觉反馈，用户感知加载时间长。

**目标**：增加一个带真实进度显示的加载动效，缓解等待焦虑，同时不影响现有游戏逻辑。

**成功标准**：
- 用户进入游戏时先看到加载屏，而不是白屏。
- 进度条和百分比真实反映图片加载进度。
- 阶段文字随资源类别切换，增强代入感。
- 加载完成后平滑淡出，进入选关界面。
- 资源失败时给用户明确选择，而不是静默失败或卡死。

## 方案选择

| 方案 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| A（推荐） | 改造 `preload()` 支持进度回调，`main.js` 驱动 DOM 加载屏 | 侵入小、真实进度、单测兼容 | 需要改 `assets.js` |
| B | `main.js` 里按资源类别手动分阶段加载 | 阶段文字天然准确 | 进度不平滑、代码分散 |
| C | 不确定动画 + 阶段文字循环 | 改动最小 | 无真实百分比，不符合用户要求 |

**采用方案 A**。

## 架构与数据流

```
index.html 加载 main.js
    ↓
boot()
    ├─ createLoadingScreen()          // 创建 DOM 加载遮罩
    ├─ await preload(onProgress)      // 加载资源 + 回调更新进度
    │       onProgress({ loaded, total, stage, percent })
    │              ↓
    │       updateLoadingScreen(...)  // 更新进度条、阶段文字、百分比
    ├─ 若有失败：showRetryDialog()    // 弹出继续/重载提示
    ├─ pause 200ms at 100%
    ├─ fadeOutLoadingScreen()         // 淡出并移除 DOM
    └─ 原有初始化：读档 / 建 state / resize / 绑定事件…
```

**关键约定**：
- `src/core/assets.js` 只负责加载和回调，不碰 DOM。
- `src/main.js` 负责加载屏的创建、更新、移除生命周期。
- `src/style.css` 负责加载屏视觉样式。

## DOM 结构与视觉样式

- 新增 `#loading` 全屏遮罩，覆盖在 `#game` canvas 之上。
- 居中卷轴面板，宽度 `min(420px, 86vw)`。
- 面板内包含：
  - 标题「成都保卫战」（暖金色，字距加宽）。
  - 横向进度条，金色渐变填充。
  - 下方一行：阶段文字居左，百分比居右。
- 整体配色延续游戏现有深棕 + 暖金风格（`#1a120b`、`#d4a574`、`#ffe0a8`）。

## 进度更新策略

- `preload()` 在启动时已知图片总数 `total`。
- 每张图片 `onload` 或 `onerror` 都视为「已完成一张」，累加 `loaded`。
- 回调参数：`{ loaded, total, stage, percent }`。
- `percent = Math.round((loaded / total) * 100)`。
- `stage` 按资源 ID 前缀/类别映射：
  - `gen_*` → 加载武将立绘…
  - `enemy_*` → 加载敌军图鉴…
  - `boss_*` → 加载名将 Boss…
  - `building_*` → 加载建筑城防…
- 阶段文字取当前加载图片所属类别中占比最高的那个，避免频繁抖动。

## 过渡动画

- 资源全部处理完毕后，进度显示 100%，阶段文字变为「准备就绪」。
- 停留 200ms，让用户确认已加载完成。
- 然后整个加载屏在约 400ms 内从 `opacity: 1` 淡到 `opacity: 0`。
- 淡出结束后从 DOM 中移除，露出后面的选关界面。

## 错误处理与失败提示

- 单张图片失败不会阻塞整体加载，`preload()` 仍将其标记为已完成（但 `assets.images` 中无此图）。
- 全部处理完后，若存在任何失败：
  - 不立即淡出。
  - 弹出古风确认提示框，文案类似：「部分军情图卷未能送达，是否继续出征？」
  - 两个按钮：
    - **继续出征**：用色块/首字回退渲染失败资源，进入游戏。
    - **重新整备**：调用 `location.reload()` 刷新页面重试。
- 若无失败，按正常过渡流程淡出。

## 测试策略

- 修改 `tests/assets.test.mjs`，在现有 mock loadImage 基础上增加进度回调断言：
  - 正常加载时回调被调用，且最终 `percent === 100`。
  - 部分失败时最终 `loaded === total` 但缺失的资源不在 `assets.images` 中。
- 浏览器手工验证：
  - 正常网络下进度条走到 100% 后淡出。
  - 模拟慢网 / 断网观察失败提示框。
  - 二次进入（缓存命中）时仍能看到 100% 停留 200ms 后淡出。
- Node 单测环境（无 DOM）下，`preload()` 本身不依赖 DOM，加载屏代码在 `main.js` 中仅在浏览器环境执行。

## 文件变更

- `src/core/assets.js`：为 `preload()` 增加可选 `onProgress` 回调。
- `src/main.js`：在 `boot()` 中创建、更新、淡出加载屏；处理失败提示。
- `src/style.css`：新增加载屏与提示框样式。
- `tests/assets.test.mjs`：补充进度回调相关断言。

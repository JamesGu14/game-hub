## 1. 目标与定位

复刻一款类《三国志曹操传》的 **Web 回合制战棋 RPG**：完整剧情、有对话、有剧情演出、有战斗界面。

| 维度 | 决策 |
|---|---|
| 受众 | James / 成年玩家为主（怀旧向，可承载文言对白与厚重剧情） |
| 范围 | **北极星 = 完整长篇正传**；v1 交付 = **引擎 + 第一章「起兵讨董」（约 5 战）** |
| 战斗深度 | **完整拟真**：格子战棋 + 兵种相克 + 升级成长 + 计略 + 地形 + 物品/宝物 + 单挑 + 阵型 + 转职 |
| 主视角 | 曹魏视角（致敬原作） |
| 美术 | **等距 3D 沙盘（C 方向）**，Three.js；**程序化低多边形**武将，参数化区分 40+ 人 |
| 镜头 | 锁定等距俯视 + 关键运镜（单挑/必杀/剧情切电影感） |
| 交付方式 | 引擎优先 + 数据驱动 + 一章一章交付；实现期用 Workflow 多 subagent 并行 |

### 核心原则
1. **引擎与内容分离**：加新关 = 加数据文件（地图 + 剧本），**不改引擎**。这是长篇不烂尾的根。
2. **数据驱动一切**：武将、兵种、计略、物品、地图、剧本、事件，全部是声明式数据。
3. **每一步可玩**：每个里程碑结束都能从头玩到当前进度、能存档续战。
4. **遵循 game-hub 约定**：原生 ES 模块、无构建步骤、中文优先、含「← HUB」返回与静音、localStorage 存档。

## 2. 技术栈与工程约定

- **渲染**：Three.js（正交相机做等距），**本地 vendored** 到 `games/caocao-zhuan/lib/three.module.js`（离线可用，参照 `tactical-strike` 的 `lib/` 做法），用 importmap 指向本地路径——不依赖 CDN。
- **语言**：原生 ES Modules，无打包/构建步骤（参照 `jungle-blitz` 的 `src/` 模块组织）。
- **存档**：`localStorage`，多存档槽 + 章节边界自动存档。
- **音频**：WebAudio 原创音效 + 简单原创古风 BGM（五声音阶程序化生成）；**无任何受版权 BGM**。
- **操作**：鼠标优先（点选/移动/菜单），键盘快捷键；手柄后续。
- **测试**：纯逻辑层（伤害公式、寻路、胜负判定、相克）做单元测试，放 `tests/`。
- **PoC 复用**：风格验证页 `.superpowers/.../iso-3d-poc.html` 里的程序化武将工厂、等距相机、单挑运镜、地形格子，直接模块化迁移为正式引擎的 `render3d/` 层。

## 3. 系统设计（完整拟真）

### 3.1 武将与属性
每个武将一条数据档案：

```
General {
  id, name(姓名), title(字), faction(wei/foe/ally/npc),
  level, exp,
  hp/maxHp(兵力), atk(武力衍生), def(防御),
  int(智力：计略威力+抗性), spd(敏捷：行动序/回避), mov(移动力),
  class(兵种 id), growth(成长型: 各属性每级增量),
  skills(已学计略 id[]), items(装备: 武器/防具/坐骑/宝物),
  ai(性格: reckless/cautious/strategist/guard),
  appearance(外观参数: armor/accent/skin/helmet/weapon/mount/scale/banner/portrait种子),
  storyFlags(剧情用)
}
```
- **「每个人有自己的特征」= appearance 参数（3D 外观 + 立绘）+ 差异化属性/成长/专属计略**。

### 3.2 兵种与相克
兵种：步兵 / 枪兵 / 骑兵 / 弓兵 / 谋士(法师) / 主将；后续章节扩展（近卫、连弩、藤甲、象兵、医者、器械等）。
相克（系数表，示意）：**枪克骑、骑克弓与步、弓克步与远程目标、步均衡**；谋士低防高计略。
每个兵种定义：移动型（地形消耗）、攻击距离、反击距离、可学计略集、转职去向。

### 3.3 战斗结算
- **物理伤害** = f(攻方有效攻击 × 兵种相克 × 地形修正 × 随机抖动) − 守方有效防御 × 地形修正。
- **反击**：守方存活且目标在其反击距离内则反击。
- **命中/回避**：受 spd 差与地形回避影响。
- **计略/法术**：火计/落雷/治疗/混乱/鼓舞/妖术等；消耗气力或次数；威力与命中受双方 int 差影响；可范围 AOE。
- **气力/士气**（可选，二期）：影响出手与计略可用。

### 3.4 地形
路（移动快）/ 草地 / 林（防+回避，骑减速）/ 山·关隘（防高、难攻、移动贵）/ 水（多数兵种不可入或重减速）/ 城门据点（占领类目标）。地形影响移动消耗、防御、回避、视野。

### 3.5 升级与成长
击杀 / 命中 / 治疗 / 达成目标得 EXP，满级提升；按兵种 `growth` 型加属性；关末统一结算并播放成长演出。

### 3.6 物品与宝物
武器 / 防具 / 坐骑 / 计略书（学计略）/ 消耗品（伤药、兵粮）/ 宝物（特定武将专属加成或解锁单挑必杀）。关间「整军」界面分配。

### 3.7 单挑（Duel）
- **触发**：剧情指定（如三英战吕布）或满足条件（武将相邻 + 概率/挑衅）。
- **演出**：切关键运镜（推近、压低、黑边、字幕），进入回合制单挑小战斗：双方轮流 攻/防/计，直到一方力竭或撤退。
- **结果**：败者重伤/退场，回主战场反映结果。是「致敬原作」的招牌演出，也是关键运镜的主用途。

### 3.8 阵型与转职
- **阵型**：队伍可选阵型（鱼鳞/锋矢/雁行…）给全体加成，影响攻防/移动取舍。
- **转职**：兵种达条件可转职（步→近卫、弓→连弩、谋士→大谋士…）。引擎在 v1 实现数据模型与钩子，第一章只轻量启用，后续章节扩展。

### 3.9 胜负条件（数据驱动，每关可配）
- 胜：击破敌主将 / 全歼 / 占领据点 / 坚守 N 回合 / 护送到达 / 复合条件。
- 败：主将（曹操）阵亡 / 指定友军全灭 / 超时。

### 3.10 敌方 AI
按兵种 + 性格参数：莽撞（直冲）/ 谨慎（守据点、集火残血、保命）/ 智将（放计略、拉扯走位）/ 守备（守点不出）。提供可调难度。

### 3.11 关间养成层
关与关之间的「整军」界面：查看/管理武将、分配宝物与装备、学计略、（后续）招募新武将、存档。

## 4. 剧情与叙事系统

### 4.1 叙事结构
- **章 → 战役 → 事件**。每战役 = 一份地图数据 + 一份剧本（战前/战中触发/战后对话 + 分支事件）。
- **对话系统**：底部对话框 + 程序化立绘头像（每武将一张，按 appearance 种子生成的水墨/低多边形风头像）+ 姓名/字 + 可选分支选项 + 立绘表情位。
- **剧情演出**：旁白、镜头切换、单挑过场、战场内触发事件（某回合/某单位死亡/到达某格触发剧情）。
- **分支**：选项与战场结果可置 `storyFlags`，影响后续对白与（后续章节）分支走向。

### 4.2 第一章「起兵讨董」战役清单（原创剧本，公有领域史/演义事件）
1. **陈留起兵**（教学战）——曹操散家财、矫诏讨董，初战小股巡兵。教学：移动 / 攻击 / 兵种 / 回合。登场：曹操、夏侯惇、夏侯渊、曹仁、曹洪。
2. **会盟酸枣**（剧情 + 小战）——十八路诸侯会盟，矛盾初现，先锋遭遇战。教学：计略 / 谋士（戏志才/荀彧早期登场）/ 地形。
3. **汜水关**——联军攻关，华雄逞威（「温酒斩华雄」作友军事件过场），曹军侧翼推进。教学：攻坚 / 关隘地形。
4. **虎牢关**——吕布当关，**三英战吕布**（单挑系统 showcase，作剧情演出），曹军主力突破。教学：以多打强 / 计略削弱强敌。
5. **荥阳追击**（章末转折）——董卓焚洛阳西逃，曹操力主追击却中徐荣埋伏。一场「虽败犹荣」的艰难战收尾，奠定枭雄基调，留下第二章引子。

> 后续章节（北极星，逐章交付）：濮阳吕布 → 兖州 → 官渡 → 平河北 → 远征 → …（每章独立 spec→实现循环）。

## 5. 引擎架构（模块）

```
games/caocao-zhuan/
  index.html            # 入口：canvas + 覆盖层 UI + importmap(本地three)
  style.css
  lib/three.module.js   # vendored Three.js
  src/
    main.js             # bootstrap；场景流：菜单→章节→整军→战斗→剧情→结算
    core/
      gameState.js      # 运行态、roster、进度、存读档(localStorage)
      eventBus.js       # 模块解耦事件总线
      rng.js            # 可种子随机（战斗抖动/可复现）
    data/
      classes.js        # 兵种定义 + 相克表
      skills.js         # 计略定义
      items.js          # 物品/宝物
      terrain.js        # 地形定义
      generals.js       # 武将档案（含 appearance 参数）
      chapters/ch01/    # 第一章：5 张战役地图 + 5 份剧本（纯数据）
    battle/
      battleController.js  # 回合状态机（玩家相/敌相/事件相）
      grid.js, pathfind.js # 格子 + A* 寻路 + 移动范围
      combat.js            # 伤害/相克/地形/反击/命中
      duel.js              # 单挑小战斗
      ai.js                # 敌方决策
      victory.js           # 胜负条件评估
      leveling.js          # 经验/升级/成长
    render3d/
      sceneManager.js   # 场景/光照/渲染循环
      camera.js         # 等距锁定 + 运镜 tween（来自 PoC）
      unitFactory.js    # 程序化武将工厂（来自 PoC）
      terrainFactory.js # 地块/地形 mesh（来自 PoC）
      banner.js, fx.js, animations.js
    story/
      scenarioRunner.js # 事件/分支执行器（驱动剧情）
      dialogue.js       # 对话框/选项
      portrait.js       # 程序化立绘头像
    ui/
      hud.js            # 回合/相位/单位信息/行动菜单
      statCard.js       # 武将档案卡
      intermission.js   # 关间整军界面
      menus.js          # 标题/暂停/胜负/存读档
    audio/
      audio.js          # 原创音效 + 程序化古风 BGM
  tests/                # 战斗/寻路/胜负/相克 纯逻辑单测
  README.md
```

**模块边界**：`battle/` 与 `story/` 是纯逻辑（不依赖 Three.js，可单测）；`render3d/` 只负责把状态画出来并播动画；`ui/` 是 DOM 覆盖层；三者通过 `eventBus` 与 `gameState` 通信。这让逻辑可测、渲染可换、内容可加。

### Hub 集成
在 `js/games.js` 增加一条：`id: 'caocao-zhuan'`，`path: 'games/caocao-zhuan/index.html'`，标签如 `['策略','战棋','三国','键鼠']`，配色国风金/朱。`index.html` 含「← HUB」返回与静音按钮，遵循现有覆盖层风格。

## 7. 交付里程碑与 subagent 拆分

**M1（v1）= 引擎 + 第一章**，分三阶段，实现期用 Workflow 编排：

- **阶段 A · 地基（先行，定接口与数据 schema）**：项目骨架、`gameState`/存档、各数据 schema（武将/兵种/计略/物品/地形/地图/剧本）、`grid`/`pathfind`、回合状态机骨架、`eventBus`。
- **阶段 B · 并行建造（多 subagent，对着 A 的接口写）**：
  1. `render3d`（迁移 PoC → 模块化的 sceneManager/camera/unitFactory/terrainFactory/fx）
  2. 战斗系统（combat/相克/leveling/victory）
  3. 计略 + 单挑 + AI
  4. 剧情系统（scenarioRunner/dialogue/portrait）
  5. 第一章数据内容（generals/classes/skills/items + 5 战地图）
  6. 第一章剧本（5 份剧情脚本，原创对白）
  7. UI/HUD/整军界面
  8. 音频
- **阶段 C · 集成 + 联调 + 测试 + Hub 接入 + 试玩验收**：把 B 各路接到状态机上跑通，单测逻辑层，注册到 hub，浏览器实玩走查第一章。

> 详细任务拆解与执行顺序在 `writing-plans` 阶段产出实现计划；本 spec 只定架构与拆分边界。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 长篇烂尾 | 引擎/内容分离 + 逐章交付，每章独立可玩可存档 |
| 3D 性能/兼容 | 已用 PoC 在浏览器验证通过；低多边形 + 实例化 + 锁定相机控制开销 |
| 战棋手感与平衡 | 逻辑层单测 + 每章实玩走查；难度可调；数值集中在 `data/` 便于调参 |
| 模块并行冲突 | 阶段 A 先冻结接口/schema，B 各 subagent 在独立目录/文件作业，C 统一集成 |
| 版权 | 全原创美术（程序化）+ 原创剧本；仅用公有领域史/演义素材 |

## 10. 验收标准（v1 / M1）

1. 从 hub 进入，标题 → 第一章开场剧情 → 第一战，全流程可玩。
2. 战斗界面：等距 3D 沙盘、点选/移动范围/攻击/计略/单挑、回合推进、胜负判定齐全。
3. 完整拟真要素在第一章可见：兵种相克、地形、升级成长、计略、单挑（三英战吕布）、物品。
4. 剧情：5 战串成「起兵讨董」完整故事弧，含战前/战后对话、立绘、关键运镜。
5. 关间整军、存读档、返回 hub、静音均可用。
6. 逻辑层单测通过；浏览器实玩无致命报错。
```

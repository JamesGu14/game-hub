# Tower Defender · 城堡美化 + 真实城池命名 设计文档

- 日期：2026-06-10
- 状态：brainstorm 定稿，待实施
- 范围：`games/tower-defender`（渲染层 board.js + 新数据层 cities.js + 4 张新 sprite）

## 1. 背景与目标

当前 `src/render/board.js` 中成都为灰色块+文字、敌营为深紫色块+红旗，均为占位（代码注释自承"色块占位"）。目标：

1. **美化**成都大本营与敌方城堡的渲染，精致度对齐现有 44 张 Kingdom Rush 风武将立绘。
2. 敌军**每座城堡**对应一座三国历史上真实的城池：**章内不重复**；章内**前期关卡用冷门城名、越往后越知名**。

## 2. 已确认决策（brainstorm 对话定稿）

| 决策点 | 结论 |
|---|---|
| 城名口径 | **每营一城**：一关 2–8 座敌营各挂一座不同真实城池，章内全部不重复 |
| 城堡造型 | **势力定制 3 款**：魏·玄黑石城 / 吴·青瓦水城 / 蛮·兽骨木寨（精致版元素清单见 §3） |
| 城名牌匾 | **脚下横牌·仅汉字**（半透深底白字，canvas 绘制；不加拼音、不用竖旗幡） |
| 实现路线 | **AI sprite**：走现有 `tools/gen-sprites.mjs`（Nano Banana）管线，黄忠锚保画风 |
| 成都 | 单独 1 张蜀汉风大城楼（金红、2×2 格），名牌走同一 canvas 系统 |

## 3. 美术资产（设计 4 款 / 本期生成 3 张）

## 4. 渲染（src/render/board.js）

- **敌营**：色块 → billboard 贴图。按 `state.level.faction` 选 `building_wei/wu/nanman`；高约 **1.6 格**（CELL=36px → ~58px），宽按图片纵横比，**底边对齐格底** + 椭圆阴影（沿用 entityRenderer 的 billboard 约定）。敌人 sprite 后画、压在城门上 = "出城"层序，天然成立。
- **成都**：色块 → `building_chengdu` 贴图，2×2 格、高约 **2.7 格**，底边对齐 castle 区域底边 + 阴影。
- **回退铁律**：任一图缺失 → 回退现有色块+文字渲染，测试环境（无 Image）照常可玩，行为与现状一致。
- **成都受损反馈**（轻量，纯 render 层读 `state.castleHp`，满血 20）：HP<50% 城楼顶画 1–3 缕程序化烟（贝塞尔曲线 + 透明度脉动）；HP<25% 烟色转火苗橙红。无新依赖、无玩法变更。

## 5. 城名数据（src/data/cities.js，新文件）

### 5.1 结构

```js
export const CITY_POOLS = { 1: [/*26*/], 2: [/*36*/], 3: [/*46*/], 4: [/*56*/], 5: [/*72*/] };
```

- 每章一个数组，**知名度升序**（最冷门在前、名城压轴），长度**精确等于**该章 camp 总需求。
- 需求推导（CAMPAIGN × TEMPLATES，样板关按 pathSubset）：
  - 第1章：L1样板3 + twoCamp 2×4 + threeCamp 3×5 = **26**
  - 第2章：L11样板4 + threeCamp 3×4 + fourCamp 4×5 = **36**
  - 第3章：L21样板5 + fourCamp 4×4 + fiveCamp 5×5 = **46**
  - 第4章：L31样板6 + fiveCamp 5×4 + sixCamp 6×5 = **56**
  - 第5章：L41样板8 + sixCamp 6×4 + eightCamp 8×5 = **72**
  - 合计 236。单测从 CAMPAIGN×TEMPLATES 推导需求并断言池长相等（模板/亚集未来变更时测试报警）。
- **地理主题**：①讨董中原（汜水关/虎牢关/宛城…）②官渡河北（白马/延津/乌巢/邺城/官渡…）③荆襄江东（柴桑/夏口/江陵/赤壁…）④西川汉中（葭萌关/雒城/剑阁/阳平关/定军山…）⑤夷陵+北伐雍凉（秭归/猇亭/街亭/陈仓/五丈原/长安…）。
- **跨章允许复用**（如长安可在第 2、5 章各出现一次）；章内严格唯一。
- 城名一律 **2–4 个汉字**、史实向（县/城/关隘/渡口均可）；名单实现期编纂，入库前给 James 过目。

### 5.2 分配算法（src/data/levels.js）

`expand(c)` 时按**章内累计 camp 数切片**：第 k 关取池 `[start, start + campCount)`（start = 章内前 k-1 关 camp 数之和），逐个写入 `camp.cityName`。纯切片 ⇒ 章内唯一、确定性（加载期无随机）、越往后越知名，三性质自动成立。

### 5.3 样板关贴题（编辑例外）

6 个手写样板关的切片位置直接放**贴题城名**（cities.js 为唯一真相源，知名度/地理排序的局部例外）：

- L1 博望坡（3 营）：宛城、叶县、堵阳（夏侯惇出兵方向）
- L50 上方谷·五丈原（8 营，第5章池尾最知名段）：渭南、郿县、武功、五丈原、陈仓、街亭、上邽、长安
- L11/L21/L31/L41 同理（当阳系/赤壁水陆营系/汉中系/夷陵系），实现期定稿。

## 6. 城名牌匾渲染

- canvas 绘制**脚下横牌**：半透深色圆角底（`rgba(20,16,24,.78)`）+ 白字（`#f5edd8`）+ 细描边，宽度随字数自适应，挂城堡格底部中央。
- 敌营用 `cp.cityName`；成都用同款**金红描边**变体写「成都」。
- 几何计算抽纯函数 `plateRect(text, cx, footY, C)`（render 目录内、无 DOM 依赖）供单测。

## 7. 测试与门禁

新增单测：
1. 每章池长度 == 推导需求（CAMPAIGN×TEMPLATES 推导）
2. 章内城名唯一（Set 断言）
3. 全部城名 2–4 个汉字
4. LEVELS 展开确定性：两次展开 cityName 分配完全一致
5. 每关 camps 均有非空 `cityName` 且关内唯一
6. `plateRect()` 几何（2/3/4 字宽度、居中）

存量门禁全部保持绿：现有 40 单测、`verify-levels.mjs`、`check-imports.sh`、headless 冒烟。冒烟补截图覆盖两款敌营城堡 + 成都（建议 L1 魏·3营 / L21 吴·5营 / L41 吴·8营），人工看图确认贴图与名牌。

## 8. 范围外（本期不做）

- 玩法不变：敌营不可攻击、不掉血；成都 HP 机制不变。
- story 文案 / storyCard / HUD / 选关界面不动。
- 旗帜飘动、火苗、水波等程序化动画层 → 二期 polish（本期 sprite 静态）。
- 蛮·兽骨木寨的图片生成 → 待出现南蛮关卡的章节时执行（设计与 prompt 已在 §3 定稿，补图即生效）。
- 音频不动。

## 9. 验收标准

1. 浏览器实玩：魏、吴关卡敌营显示对应势力城堡贴图 + 城名横牌；成都显示蜀汉大城楼 + 金红名牌；成都掉血至 <50%/<25% 出现烟/火反馈。
2. 任一章内逐关查看：城名无重复，知名度总体由冷门到知名递进（样板关例外允许）。
3. 全部单测/门禁绿；无图环境（单测/CI）回退色块不报错。

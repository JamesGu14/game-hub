# 设计稿 Review：JUNGLE WARRIOR（魂斗罗复刻）

> 评审对象：`docs/superpowers/specs/2026-06-07-jungle-warrior-design.md`
> 评审日期：2026-06-07
> 评审人：Sisyphus（基于 FC 魂斗罗原始资料调研）

---

## 评审结论

**整体结构清晰、模块边界合理、里程碑切分务实。** 但在核心机制还原度、年龄适配和遗漏的经典元素上有若干需要关注的问题。

| 维度 | 评分 | 说明 |
|------|------|------|
| 架构设计 | A | 对齐 pixel-quest，依赖方向清晰，状态机完整 |
| 技术可行性 | A | 纯原生 JS + Canvas，无外部依赖，风险低 |
| 魂斗罗还原度 | B | 瞄准系统、操作映射、部分经典元素有偏差 |
| 儿童友好度 | B+ | 无限复活合适，但键盘映射和反馈机制可优化 |
| 可扩展性 | A- | 难度参数化好，但缺少难度分级机制 |

---

## 严重问题（建议修改）

### 1. 8方向瞄准系统 ≠ 魂斗罗操作逻辑

| 维度 | 原版魂斗罗 | 当前 Spec |
|------|-----------|-----------|
| 操作方式 | **移动即瞄准**（按右上 = 人物朝右上方跑并斜上射击） | **移动/瞄准分离**（moveX + aimUp/aimDown 修饰符） |
| 复杂度 | 2个按键同时按（方向+射击） | 最多3个按键组合（移动+瞄准修饰+射击） |
| 对应游戏 | 经典魂斗罗、马里奥 | 合金弹头、现代双摇杆射击 |

**问题**：这是《合金弹头》的操作模式，不是魂斗罗的操作模式。7岁孩子理解"移动方向=射击方向"更直觉。

**建议**：提供两种操作模式可选——
- **经典模式**（默认）：方向键同时控制移动和瞄准（按↗则朝斜上跑+射）
- **现代模式**（进阶）：双摇杆/分离式，适合触屏

---

### 2. "极致休闲"与魂斗罗核心体验的冲突

当前设计：被击中 → 原地无限复活 + 不丢武器 + 无命数概念 + 仅计时

**问题**：魂斗罗的核心乐趣循环是「背板 → 肌肉记忆 → 一命通关的成就感」。无限复活虽然适合小朋友，但会彻底消除紧张感和重复挑战的动力。

**建议**：增加**难度分级**（选关界面可选）：
- **儿童模式**（默认）：无限复活、复活短暂无敌、关卡内 checkpoint
- **经典模式**：3条命、掉完 Game Over、从头开始（保留选关存档，只是单关内变难）
- 这样孩子长大后可以自己切换到经典模式，游戏生命周期更长

---

### 3. 键盘映射对7岁不友好

当前映射：`J=射击 / K=跳跃 / L=切换武器 / Shift=跑`

**问题**：小朋友的手指小，JKL排布不适合同时按。魂斗罗经典操作是：
- 方向键移动/瞄准
- `Z` 或 `空格` 射击（单发/连发）
- `X` 跳跃

**建议**：默认采用更适合小手的映射：
```
←→↑↓ / WASD = 移动+瞄准（经典模式）
空格 / Z = 射击（按住连发）
X / K = 跳跃
C / L = 切换武器（或不做单独键，直接拾取自动换）
```

## 中度问题（建议补充）

### 4. 缺少魂斗罗最标志性的"Konami Code"

上上下下左右左右BA Start = 30条命，这是**魂斗罗最深入人心的文化符号**，也是孩子会觉得"酷"的东西。

**建议**：在标题画面保留这个彩蛋——输入后儿童模式变为30条命模式（或解锁隐藏内容）。

---

### 5. 武器系统不完整

| 原版道具 | 当前 Spec | 状态 |
|---------|-----------|------|
| M 机枪 | ✅ M 机枪 | 保留 |
| S 散弹 | ✅ S 散弹 | 保留 |
| L 激光 | ✅ L 激光 | 保留（但原版FC激光较弱，注意平衡） |
| F 火球 | ✅ F 火球 | 2代改为蓄力火炎 |
| R 射速提升 | ❌ 未做 | **缺失** |
| B 无敌屏障 | ❌ 未做 | **缺失** |
| 全灭（无字母） | ❌ 未做 | **缺失** |

**建议**：至少补充 **B 无敌屏障**——对孩子非常友好，拾取后有5秒无敌+撞敌杀敌，成就感极强。R射速提升也可以作为通用 Buff。

---

### 6. 关卡设计遗漏经典类型

Spec 明确排除"俯视/纵深基地关"（Out of Scope #2），但 FC 魂斗罗的**基地关（第2关俯视视角）**是非常经典的关卡类型，也是系列标志性特色。

**建议**：如果技术架构允许（char-grid 地图 + 俯视摄像机），M4 阶段可以考虑加一个简单的俯视关（类似 Mini 版），哪怕只有1个。

另外，瀑布关（L3）原版是**纵向向上卷轴**，但 spec 描述的"移动平台 + 空中飞兵"仍是横版逻辑。

---

### 7. 武器胶囊机制描述有误

当前：「空投箱(Capsule)沿固定路径飞入，被任意子弹击中→爆出武器图标」

原版：红鹰胶囊从屏幕外飞入，**玩家子弹击中后**掉落闪烁的武器字母图标，**玩家触碰拾取**。

**区别**：原版是"打中红鹰 → 掉落字母 → 触碰换武器"，不是"打中空投箱"。建议还原这个机制，对小朋友来说"打中飞来的红鹰掉宝贝"是很有趣的反馈。

---

## 轻度问题 / 优化建议

### 8. BOSS 命名缺乏魂斗罗味

当前 BOSS 名：Armored Gate Cannon / Mech Core / Gunship / Snow Tank / Alien Heart

原版 BOSS 名风格：激震砲デストロイ / 独炎眼ガルマキルマ / 陰獣魔神像グロマイデス / 兜鬼巨神兵ゴルデア / 天王創魔心ゴメラモスキング

**建议**：给 BOSS 加一些"中二感"的命名，孩子会觉得更酷。比如：
- 装甲门炮 → **震地要塞·铁壁** / **Destroy Cannon**
- 机械核心 → **独眼核心·加尔玛**
- 武装直升机 → **旋翼死神·瓦尔基里**
- 最终 BOSS → **创魔之心·戈梅拉**

---

### 9. 缺少正向反馈强化（对儿童重要）

7岁孩子需要强烈的即时成就感反馈：
- **连击计数**：连续杀敌 ×2 ×3 ×4...
- **得分飘字**：击中敌人弹出 "+100" 飘字动画
- **通关评价**：根据死亡次数、用时给 ⭐⭐⭐ 评级
- **爆炸粒子**：当前 spec 提到了，确保足够夸张显眼

建议在 HUD 部分补充这些儿童友好的反馈设计。

---

### 10. 单测覆盖有遗漏

当前测试列表缺少：
- `input.test.mjs`：三端输入映射、Intent 生成
- `collision.test.mjs`：子弹-敌人、玩家-敌人、子弹-地形
- `capsule.test.mjs`：红鹰飞行路径、击中掉落、拾取切换

## 总体评价

这份 spec 作为**"受魂斗罗启发的休闲横版射击游戏"**的设计非常合格；但如果目标是**"给儿子复刻经典魂斗罗体验"**，建议在 P0/P1 项上做些调整，保留更多原版的标志性元素，同时通过难度分级让7岁孩子能享受、长大后还能挑战。

## 补充：需求不明确点（实现视角）

> 以下是从"如果今天就开始写代码"的角度，发现的需求缺失、歧义或边界条件未定义的问题。按**阻塞程度**排序。

---

### 🔴 高优先级（缺少则无法准确实现或体验大幅偏差）

#### H1. 角色与敌人的物理尺寸未定义

**缺失信息**：
- 玩家角色像素尺寸（宽×高）
- 玩家受击框（hitbox）与视觉框是否一致？卧倒时受击框如何变化？
- 各类敌人的尺寸和受击框
- TILE 世界单位 = 多少像素？

**影响**：physics.js 的 AABB 碰撞、关卡 grid 设计、相机跟随逻辑全部依赖这些基准值。

**建议**：在 `config.js` 中统一定义 `PLAYER = { w: 16, h: 24, hitbox: {x,y,w,h} }` 等。

---

#### H2. 跳跃物理参数缺失

**缺失信息**：
- 重力加速度（px/s²）
- 跳跃初速度（px/s）
- Coyote time（离开平台后仍可跳跃的缓冲时间）
- Jump buffer（提前按跳跃键的缓冲时间）
- Jump cutoff（松键后速度衰减比例，实现"按越久跳越高"）
- 最大下落速度（terminal velocity）

**影响**：直接决定手感。pixel-quest 已有这些值，但设计稿未说明是否直接复用还是单独调参。

**建议**：明确 `config.PLAYER.jump = { gravity: 1800, velocity: 420, coyote: 0.08, buffer: 0.1, cutoff: 0.4, maxFall: 600 }`。

---

#### H3. F 火球弹道类型歧义

**设计稿**：「抛物/螺旋、可越障、小范围」

**问题**：**抛物线**和**螺旋**是两种完全不同的弹道物理。
- 抛物线 = 受重力影响，有落点预判
- 螺旋 = 正弦轨迹，水平匀速前进

**影响**：weapons.js 中 `fire()` 的实现完全不同。

**建议**：明确为**抛物线**（魂斗罗原版 F 是旋转火球，近似抛物线；螺旋更难实现且不符合原版）。

---

#### H4. R 射速叠加公式与上限未定义

**设计稿**：「提升当前主武器射速/弹速（可叠加）」

**缺失信息**：
- 叠加是加法还是乘法？（如 cooldown × 0.8 还是 cooldown - 0.02s）
- 最多叠加几层？
- 是否影响弹速？射速和弹速是否同步提升？
- 经典模式死亡后重置，休闲模式保留——那休闲模式能否无限叠加？

**影响**：平衡性问题。无限叠加 M 机枪可能变成激光雨。

**建议**：`R = { cooldownMul: 0.85, speedMul: 1.1, maxStack: 3 }`，叠加公式为乘法，上限3层。

---

#### H5. 无敌时间（i-frame）具体时长未定义

**缺失信息**：
- 休闲模式复活后的无敌闪烁时长
- 经典模式复活后的"短无敌"时长
- B 屏障的无敌时长
- 闪烁频率（如 100ms 切换一次 visible）

**影响**：太长则无聊，太短则连续受击挫败。

**建议**：休闲复活 = 2.0s；经典复活 = 1.5s；B 屏障 = 5.0s；闪烁周期 0.12s。

---

#### H6. 关卡长度单位与红鹰触发机制不明

**缺失信息**：
- 关卡总长度是多少？（像素？屏幕宽度的倍数？）
- 红鹰 `falcons: [ {drop:'S', path, atX} ]` 中的 `atX` 语义：
  - 是玩家 x 坐标到达时触发？
  - 还是时间触发？
  - 触发后红鹰从哪里进入？（左/右/上？）
- `path` 的数据格式是什么？（点数组？贝塞尔控制点？匀速折线？）
- 红鹰飞行速度？
- 红鹰被击中后，掉落的字母图标持续多久后消失？
- 多颗子弹同时击中红鹰，掉几个图标？

**影响**：levels.js 数据格式和 game.js 触发逻辑的实现。

**建议**：
- 关卡长度用像素（如 L1 = 4096px ≈ 8 屏幕宽）
- `atX` = 玩家相机右边界到达该 x 时触发
- `path` = `[{x,y}, ...]` 折线路点，匀速插值
- 红鹰从屏外左侧飞入，速度 120px/s
- 字母图标掉落，闪烁（0.2s 周期），持续 8s 后消失
- 无论多少子弹击中，只掉 1 个图标

---

#### H7. 敌人具体数值全部缺失

**缺失信息**：
- Runner：速度、HP、是否掉落悬崖、是否会被地形阻挡
- Jumper：触发扑击的距离、跳跃初速度/角度、HP
- Gunner：HP、射击间隔、子弹速度、子弹伤害
- Turret：HP、扇形角度、连射颗数、射击间隔
- Flyer：飞行速度、正弦振幅/频率、投弹间隔、HP
- 所有敌人的**得分**
- 敌人的生成逻辑（一次性摆放 vs 波次生成 vs 进入视野生成）

**影响**：entities.js 无法写出具体的 update 逻辑。

**建议**：在 `config.ENEMIES` 中统一定义各类型参数，并明确生成逻辑为"进入相机视野 + 一定距离阈值"时激活。

---

#### H8. ⭐ 评级标准完全未定义

**设计稿**：「3⭐=本关 0 死且用时达标 / 2⭐=少量死 / 1⭐=通关」

**缺失信息**：
- "用时达标"——每关的目标时间是多少？（如 L1 = 120s, L2 = 180s...）
- "少量死"——具体阈值？（1-2次？≤3次？）
- 2⭐ 是否也考虑用时？还是只看死亡数？
- 休闲模式也有 ⭐ 吗？（休闲无限复活，死亡数意义不大）

**影响**：save.js 的 `markCleared()` 和结算 UI 无法计算。

**建议**：
```js
// config.STARS
{ timeThreshold: {gold:90, silver:150}, deaths: {3star:0, 2star:2} }
// 休闲模式：只按时间评星，死亡不扣分
// 经典模式：时间和死亡共同决定，取最低档
```

---

#### H9. BOSS 机制大量缺失

**缺失信息**：
- `phases[]` 按血量切换——阈值是多少百分比？（如 75%/50%/25%？）
- `weakpoint` 窗口——是特定部位（如头部）？还是特定时机（如攻击后硬直）？
- BOSS 的尺寸、移动方式（固定/左右移动/追逐？）
- BOSS 子弹/攻击的具体参数（速度、数量、伤害）
- 死亡演出时长？（如 2s 爆炸 + 0.5s 白屏）
- BOSS 战期间是否锁定相机？（不让玩家继续前进）

**影响**：每个 BOSS 都需要单独设计，但设计稿只给了名字。

**建议**：M2 阶段先定义 L1 BOSS「震地要塞·铁壁」的完整参数作为模板，后续 BOSS 套用。

---

### 🟡 中优先级（有惯例可先用默认值，但最好明确）

#### M1. 复活「最近安全落脚点」算法未定义

**设计稿**：「原地（或最近安全落脚点）即时复活」

**问题**：如果玩家在坑边倒下，原地复活会再次掉坑。"最近安全落脚点"的判定：
- 向左/右搜索多远？
- "安全"的定义 = 脚下有地面 + 上方无即死区？
- 如果左右都没有安全点？（关卡设计错误，但需兜底）

**建议**：从倒下位置向左右各搜索最多 3 个 TILE，找第一个脚下有 solid 地面、头顶无 hazard 的位置；找不到则回到关卡出生点。

---

#### M2. 视差背景层数与速度比

**缺失信息**：
- 几层视差？（天空/远山/近山/地面？）
- 每层相对相机的滚动速度比？
- 是否循环？

**建议**：先定 3 层（天空 0.2x、山 0.5x、树 0.8x），循环平铺。

---

#### M3. 连击系统参数

**缺失信息**：
- 「短时间内」= 几秒？（如 2.5s 内连续击杀）
- 加分倍率：×2 = 2倍分？×3 = 3倍分？
- 连击显示的最大值？
- 连击中死亡是否打断？

**建议**：窗口期 2.5s；倍率 = 基础分 × min(连击数, 5)；死亡不打断连击（休闲模式死亡太频繁）；经典模式死亡打断。

---

#### M4. 屏幕震动参数

**缺失信息**：
- 震幅（像素）
- 时长
- 衰减曲线（线性/指数）
- 什么事件触发？（BOSS 死亡？玩家受击？大爆炸？）

**建议**：震幅 4px、时长 0.3s、指数衰减；BOSS 死亡和大型爆炸触发。

---

#### M5. `world` 对象接口契约未定义

**设计稿**：「实体只读 `game` 暴露的 `world`」

**缺失信息**：`world` 有哪些字段和方法？
- `world.grid`？`world.player`？`world.enemies`？
- `world.addScore(n)`？`world.spawnParticles(...)`？`world.playSound(...)`？
- 实体通过 `world` 能做什么？不能做什么？

**建议**：在 §2 或附录中定义 `world` 接口：
```js
// world 暴露给实体的只读/可调用接口
{
  grid, player, enemies, bullets, particles,
  camera, mode, // 只读
  addScore(n), spawnEnemy(type,x,y), playSound(id),
  shake(intensity), addFloatText(text,x,y) // 可调用
}
```

#### M6. 存档数据冗余

**问题**：`clearedLevels` 数组和 `perLevel` 对象有冗余——cleared 状态完全可以从 `perLevel[id].cleared` 推导。

**建议**：去掉 `clearedLevels`，简化数据模型，降低不一致风险。

### 本轮新发现的不明确点（8 个）

#### N1. R 射速增益缺"持续时间"和"满层后拾取处理"

**设计稿 §3.3**：「提升当前主武器射速/弹速（可叠加）」
**§13**：「乘法·上限 3 层」

**仍缺失**：
- R 的**持续时间**是多少？（如 15 秒？无限？）
- 已有 3 层 R 时，再拾取 R 是**浪费**还是**刷新持续时间**？
- 休闲模式保留 R，那跨关卡是否保留？（如 L1 叠了 3 层 R，进 L2 还有吗？）

**建议**：
```js
R = { cooldownMul: 0.85, speedMul: 1.1, maxStack: 3, duration: 20 }
// 满层再拾取 = 刷新持续时间；跨关卡清空（每关独立）
```

---

#### N2. B 屏障增益缺"持续时间"和"叠加处理"

**设计稿 §3.3**：「拾取后数秒无敌 + 撞敌秒杀」
**§13**：「屏障 5s」

**仍缺失**：
- 已有 B 时，再拾取 B 是**延长 5s**还是**浪费**？
- B 的持续时间在 HUD 上如何显示？（倒计时条？闪烁图标？）

**建议**：
```js
B = { duration: 5, extendable: true } // 可叠加延长
// HUD：B 图标外圈倒计时环
```

---

#### N3. 红鹰触发是否可重复？

**§13**：「atX = 相机右边界到达该 x 时触发」

**问题**：
- 红鹰是**一次性触发**还是**可重复触发**？
- 如果玩家往回走（魂斗罗限制往回走，但触屏可能误操作），相机左移后再右移，会再次触发吗？
- 红鹰飞离屏幕后是否销毁？
- 红鹰被击中前玩家走远了，红鹰会自己飞走吗？

**建议**：明确为 **一次性触发**（进入关卡后首次到达 atX 即触发，触发后标记 `spawned: true`）；红鹰从左侧飞入→沿 path 飞出右侧→自动销毁；玩家未击中不补偿。

---

#### N4. H1/H2 缺少 pixel-quest 具体引用

**§13**：「H1 延后到 config.js」「H2 直接复用 pixel-quest」

**问题**：实现者需要去翻 pixel-quest 代码找基准值，增加了认知负担。

**建议**：在 §13 或 writing-plans 中注明：
```
pixel-quest 参考值（src/config.js）：
- TILE = 16px
- PLAYER = { w: 14, h: 20 }（视觉），hitbox = { x:1, y:4, w:12, h:16 }
- GRAVITY = 1800, JUMP_VELOCITY = -420, COYOTE = 0.08s, BUFFER = 0.1s
```
或直接复制一份基准值到 warrior 的 config.js 中作为起点。

---

#### N5. M1 终点与 M2 BOSS 触发区的兼容

**M1**：「到达关尾终点判过关（先无 BOSS）」
**M2**：「L1 BOSS 震地要塞」

**问题**：M1 的"关尾终点"在 M2 会被替换为 BOSS 战触发区。两者的数据格式和逻辑是否兼容？
- M1 终点：一个 x 坐标？一个特殊地块？一个 invisible trigger？
- M2 BOSS：也是 trigger，但触发后进入 BOSS 战而不是直接过关。

**建议**：统一为 **Trigger Zone** 机制：`{ type: 'finish', x, w }`（M1）→ `{ type: 'boss', x, w, bossType }`（M2）。M1 的 finish trigger 在 M2 直接替换为 boss trigger，关卡 grid 不变。

---

#### N6. 敌人激活距离阈值仍缺失

**§13**：「进相机视野 + 距离阈值时激活」

**问题**："距离阈值"是多少？是相机外额外 N 个像素就开始 update？还是严格进入相机后才激活？

**影响**：如果严格进入相机才激活，玩家快速推进时会看到敌人"凭空出现"；如果相机外太远就激活，会浪费 CPU。

**建议**：`激活阈值 = 相机边界外 1.5 屏宽`，即敌人在 `[camera.x - 1.5*width, camera.x + 2.5*width]` 范围内时 update（右侧多给 1 屏用于预生成）。

---

#### N7. 关卡时间阈值缺示例值

**§13**：「每关设 config.STARS.timeThreshold」

**问题**：5 关的目标时间各是多少？没有示例值，实现者无从猜测。

**建议**：给出 L1 示例：
```js
// config.STARS
{
  1: { gold: 90, silver: 150 },   // L1 丛林，约 90s 金牌
  2: { gold: 120, silver: 200 },  // L2 基地，更长
  // ... 3~5 留到 M4 调
}
```

---

#### N8. 改键 UI 入口未定义

**§7**：「键位可在设置页自定义，存 save.settings.keymap」

**问题**：
- "设置页"从哪里进入？标题页按钮？游戏中 ESC 暂停菜单？
- 改键界面是弹窗还是新页面？
- 触屏上改键是否有意义？（触屏按钮位置可调？）

**建议**：v1 简化处理——标题页加「设置」按钮 → 弹窗改键；触屏控件位置 v1 固定不改。writing-plans 中定义 settings modal 的交互流程。
